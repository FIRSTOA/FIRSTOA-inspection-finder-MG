# 홈 디자인 3차 설계안 — "수치·팀 구분이 잘 보이게" (2026-10-24 저녁, 디자인실 윤화면)

사용자(CS 팀장) 말: "홈화면 좀 더 수치 같은 거나 팀 구분 이런 게 더 잘 보이게 할 수도 있나? 최상의 디자인 한번 뽑아보자."
**이 문서는 설계안만이다. 코드는 아직 고치지 않았다.** 사용자가 3안 중 하나를 고르면 그때 구현한다.
오전 개편 결정(docs/tasks/home-redesign-2026-10-24.md)은 그대로 둔다: 위젯 4개, 달성표가 주인공, 이동 단추 없음(SHOW_OPEN_LINKS=false), 금일 현황 기본 숨김, 미처리·OKR 반반(2x2).

## 1. 지금 화면의 문제 진단 (실측)

기준 파일: src/kpi/KpiWidgets.view.tsx 608~838줄(달성표), 160~214줄(색 토큰). 폭은 사이드바 `w-64`(256px, App.tsx 5153줄)·홈 `px-6`·카드 `px-4`·표 `px-3` 를 빼고 계산한 **추정값**이다(브라우저 실측은 QA에서).

### 1-1. 숫자 크기·대비
| 자리 | 지금 | 문제 |
|---|---|---|
| CS 전체 실적 | `text-[20px]` font-mono, 상태색 | 표에서 가장 큰 숫자인데 카드 제목(17px)과 거의 같다. "주인공 숫자"로 느껴지지 않음 |
| CS 전체 `/목표` | 14px slate-500 | 실적과 같은 줄·비슷한 크기라 한 덩어리로 읽힘 |
| 팀 칸 실적 | `text-[11.5px]` | CS(20px)의 0.57배. 행 이름(13px)보다도 작다 |
| 팀 칸 `/목표` | 11.5px slate-500 | 어두운 바탕(#151A23 계열)에서 대비 약 **3.7:1** — 본문 기준 4.5:1 미달 |
| 팀 칸 % | 11px slate-400 | 실적·목표·% 세 숫자가 96px 칸 하나에 같은 크기로 붙어 `12/24 50%` — **큰 숫자가 없다** |
| 팀 칸 막대 | `h-1`(4px), 점선 페이스 없음 | 색(상태)이 보이기엔 너무 얇다. CS 막대는 h-2(8px)+점선 |
| 상태 알약 | 10.5px | 카드 규칙(src/ui/card.ts "글자 11px 미만 금지") 위반 |
| 표 머리줄·단위 줄 | 10.5px | 같은 규칙 위반 |

### 1-2. 팀 칸(A/B/C/D/CSS) 구분이 약한 이유
1. **팀 색이 앱 어디에도 없다.** `팀 색`·`teamColor`·`TEAM_COLOR` grep 0건. 팀은 글자(A·B·C·D·CSS)로만 구분된다.
2. **머리줄이 다른 열과 똑같다.** "A팀"이 "지표"·"상태"·"CS 전체"와 같은 10.5px slate-400. 팀 묶음이 시작된다는 표시가 없다.
3. **칸 사이 경계가 없다.** 열 간격 `gap-2`(8px)뿐, 세로선·배경 띠 없음 → 팀 5칸이 숫자 한 줄로 이어져 보인다.
4. **팀 칸이 CS 칸의 축소판이다.** 둘 다 `실적/목표 + % + 막대` 구조라, 팀 칸은 "CS 칸 꼬리"처럼 읽힌다.
5. **칸 폭이 좁다.** `TABLE_GRID = [1.7fr 4.75rem 1.5fr repeat(5,1fr)]` → 1280px 화면에서 팀 칸 약 **96px**, CS 약 144px, 지표명 약 163px(1920px 화면에선 팀 칸 약 174px). 96px 안에 숫자 3개가 들어간다.
6. **폰에서는 팀이 아예 안 보인다.** 폰 카드(813~833줄)는 `CsSummary` 만 그린다. 팀 숫자는 카드를 펼쳐야(RowDetail) 나온다.
7. 다른 박스도 같다: 미처리 팀 탭은 11px `py-1` 알약(높이 약 22px, 손가락 크기 min-h-11 미달), OKR 범위 칩·파트 미니 바도 글자만.

## 2. 디자인 원칙 (5개)

1. **한 칸에 큰 숫자 하나 + 작은 보조 숫자.** 팀 칸 큰 숫자 = 달성 %(팀마다 인원·목표가 달라 %가 비교 기준), 보조 = `실적/목표`. CS 전체 큰 숫자 = 실적(28px) + `/목표`·% 는 작게.
2. **색은 한 자리에 한 뜻만.** 상태색(달성 초록·순항 파랑·부족 빨강·목표 없음 회색)은 **숫자·막대·칸 배경**에만. 팀 색은 **팀 글자 배지·머리줄 띠·탭 점**에만. 한 칸 안에서 두 색이 겹치지 않게.
3. **팀마다 고정 색, 상태색과 안 겹치는 색.** 사용자 예시(A 파랑·B 초록)는 순항(sky)·달성(emerald)과 겹쳐서 쓰지 않는다. 제안 팔레트(어두운 바탕 / 밝은 바탕):

   | 팀 | 색 | 어두운 바탕 | 밝은 바탕 | 이유 |
   |---|---|---|---|---|
   | A | 남색 | `indigo-400` | `indigo-600` | 순항 sky 와 색상각 40° 이상 차이 |
   | B | 연두 | `lime-300` | `lime-600` | 달성 emerald 보다 노란 쪽 |
   | C | 자주 | `fuchsia-400` | `fuchsia-600` | 부족 rose 보다 보라 쪽 |
   | D | 주황 | `orange-400` | `orange-600` | 달성표 상태에 주황 없음 |
   | CSS(E) | 청록 | `teal-300` | `teal-600` | 지원팀 — emerald 와 가까워 **반드시 글자 배지와 함께** |

   팀 색은 항상 글자(A·B·C·D·CSS)와 같이 나온다(색약 대비 — 색만으로 구분하지 않음).
4. **상태는 색 + 글자 둘 다.** 알약 글자(달성·순항·부족·목표 없음·준비 중)는 유지하고 11px 로 올린다. 팀 칸도 색만이 아니라 % 숫자로 판단 가능하게.
5. **폰은 카드, 팀은 카드 안 5칸 띠.** 가로 스크롤 없음. 390px 에서 팀 5칸(칸당 약 62px)을 접지 않고 바로 보이게.

## 3. 달성표 새 모양 3안 (PC 한 행 = 지표명 | 상태 | CS 전체 | A B C D CSS)

공통(3안 모두): 머리줄 팀 열에 **팀 색 띠(3px) + 글자 배지**, 표 글자 최소 11px, 준비 중·실패 행은 지금처럼 팀 칸 자리를 한 칸으로 합쳐 "준비 중 · SQL 실행 대기"(점선 회색)/"불러오지 못했습니다"(빨강), 빈 상태 문구 그대로, 로딩은 KpiWidget 골격 그대로.

### (가) 팀 색 띠 칸 — 칸마다 왼쪽 팀 색 띠 + 세로 막대 + 숫자
```
 지표               상태    CS 전체                    A        B        C        D        CSS
                                                     ━━━━━    ━━━━━    ━━━━━    ━━━━━    ━━━━━
 ▸ 블로그 답글      [부족]  18 /40   45%             ┃▮ 6/8   ┃▯ 2/8   ┃▮ 5/8   ┃▯ 1/8   ┃▮ 4/8
   건 · 인당 주 2           ███████░░░░░┊░░           ┃  75%   ┃  25%   ┃  63%   ┃  13%   ┃  50%
 ▸ 오버홀           [순항]  31 /40   78%             ┃▮ 8/8   ┃▮ 7/8   ┃▮ 6/8   ┃▮ 5/8   ┃▮ 5/8
   점 · 인당 주 2           ████████████┊░            ┃ 100%   ┃  88%   ┃  75%   ┃  63%   ┃  63%
   (┃ = 팀 색 3px 세로 띠, ▮/▯ = 상태색 세로 막대 6×28px, 숫자 15px)
```
- 장점: 모든 칸에 팀 색이 있어 "어느 팀 칸인지"는 가장 확실. 표를 길게 내려도 팀을 놓치지 않음.
- 단점: 본문에 팀 색 5개 × 행 수(주요 7행 = 35개 띠)가 깔려 **색이 시끄럽다**. 한 칸에 팀 색 띠 + 상태색 막대가 같이 있어 원칙 2(한 자리 한 뜻) 위반. 세로 막대는 페이스 점선을 넣기 어렵다.
- 폰(390px): 카드 아래 5칸 띠에 같은 띠·막대를 줄이면 칸당 62px 에 숫자가 겨우 들어감(`6/8` 만, % 생략).
- 난이도: 중. KpiWidgets.view.tsx 약 130줄(TeamCell 새로·머리줄·폰 띠·Bar 세로형 추가) + 새 파일 teamColors.ts 약 30줄.

### (나) 상태 타일 — 팀 칸 = 상태색 배경 타일 + 큰 % (추천)
```
 지표               상태    CS 전체                  ┌A──────┐┌B──────┐┌C──────┐┌D──────┐┌CSS────┐
                                                    (남색 띠) (연두 띠) (자주 띠) (주황 띠) (청록 띠)
 ▸ 블로그 답글      [부족]  18/40          45%       │  75%  ││  25%  ││  63%  ││  13%  ││  50%  │
   건 · 인당 주 2           ██████░░░░░┊░░            │  6/8  ││  2/8  ││  5/8  ││  1/8  ││  4/8  │
                                                    (파랑 옅은 배경)(빨강)(파랑)  (빨강)  (파랑)
 ▸ 오버홀           [순항]  31/40          78%       │ 100%  ││  88%  ││  75%  ││  63%  ││  63%  │
   점 · 인당 주 2           ██████████┊░░             │  8/8  ││  7/8  ││  6/8  ││  5/8  ││  5/8  │
 ▸ 받은 칭찬        [목표없음] 42 건  ↗+6 지난주     │   9   ││  11   ││   8   ││   7   ││   7   │  (회색 타일, 큰 숫자 = 실적)
```
- 모양: 타일 = `rounded-lg` + 상태색 옅은 배경(달성 `emerald-500/15`·순항 `sky-500/12`·부족 `rose-500/18`·목표 없음 `white/[0.04]`) + 큰 % `text-[18px]` 상태색 + 아래 `실적/목표` 11px slate-400. 타일 사이 6px 틈 → 팀 5칸이 또렷이 끊긴다. 팀 색은 **머리줄 띠·배지에만**.
- CS 전체: 실적 `text-[28px]`, `/목표` 15px slate-400, % 는 13px 알약, 막대 h-2.5 + 페이스 점선(지금 것 유지).
- 장점: 표를 훑으면 **빨간 타일 = 뒤처진 팀**이 바로 보인다(사용자가 원하는 "수치·팀 구분" 둘 다). 본문 색 뜻이 상태 하나뿐이라 헷갈리지 않음. 숫자 크기 CS 28 > 팀 18 > 보조 11 로 위계가 분명.
- 단점: 팀 칸에서 실적 건수가 작아진다(11px). 목표 없는 지표는 회색 타일이라 덜 눈에 띔(의도된 것). 옅은 배경의 대비는 QA에서 실측 필요.
- 폰(390px): 카드 아래에 5칸 미니 타일 띠(칸당 약 62px, 글자 배지 + % 15px, 상태색 배경) — 펼치지 않아도 팀이 보인다.
- 난이도: 중하. KpiWidgets.view.tsx 약 100줄(TeamCell·머리줄·CsSummary 크기·폰 띠·StatusPill 11px) + teamColors.ts 약 30줄. 행 높이 min-h-14 → min-h-16(64px), 주요 7행 ≈ 450px 로 4x2 안에 들어감.

### (다) 두 줄 행 — 위 숫자 줄 · 아래 팀 미니 막대 줄
```
 ▸ 블로그 답글   건 · 인당 주 2                       [부족]        18 / 40   45%
   ████████████████████░░░░░░░░░░░░░░┊░░░░░░░░  (CS 전체, 폭 전체)
   [A] ███░ 6/8 75%   [B] █░░░ 2/8 25%   [C] ██░░ 5/8 63%   [D] ░░░░ 1/8 13%   [CSS] ██░░ 4/8 50%
 ───────────────────────────────────────────────────────────────────────────────
 ▸ 오버홀       점 · 인당 주 2                       [순항]        31 / 40   78%
   ...
   ([A] = 팀 색 글자 배지, 막대 = 상태색)
```
- 장점: CS 숫자를 가장 크게(32px) 둘 수 있고, 팀 막대가 길어 비교하기 쉽다. 폰과 PC 구조가 같다.
- 단점: 행 높이가 약 1.6배(약 100px) → 주요 7행이 4x2(약 2×10rem 기준)를 넘어 **카드 안 세로 스크롤**. [전체 지표](20행 이상)는 매우 길어진다. 표의 "열"이 사라져 팀끼리 세로로 훑는 비교(A팀 전 지표)가 어렵다.
- 폰(390px): 위 줄은 그대로, 아래 팀 줄은 2줄(3+2)로 접힘 — 카드가 가장 길어진다.
- 난이도: 중상. KpiWidgets.view.tsx 약 160줄(PC 표·폰 카드 둘 다 새 구조) + teamColors.ts + 4x2 높이 조정 검토(HomeKpiGrid.view.tsx).

### 추천: **(나) 상태 타일**
이유: 사용자 요구 두 가지(수치가 크게, 팀이 갈라져 보이게)를 가장 적은 변경으로 동시에 만족하고, 본문 색 뜻이 상태 하나라 오전 개편의 "상태 알약" 체계와 충돌하지 않는다. 행 높이가 거의 그대로라 4x2 배치·주인공 구조를 건드리지 않는다.

## 4. 미처리·OKR 박스에 같은 팀 색 적용안

### 미처리(HomeUnhandledPanel.tsx)
- 팀 탭 [A]~[E]: 글자 앞 **팀 색 점(size-2)** + 높이 min-h-11(지금 약 22px → 손가락 크기). [전체]·[경영][운영][영업][기타]는 점 없음(부서는 팀 색 없음).
- 탭 안 건수는 지금처럼 빨강(rose-200)/0이면 회색 — 상태색 그대로.
- 목록 줄의 팀 글자(75줄, 지금 slate-500)를 팀 색 글자 배지로(11px). 경영·운영·영업은 회색 그대로.
```
 미처리 435건
 (전체)(●A 31)(●B 12)(●C 40)(●D 9)(●CSS 3)(경영 5)(운영 2)(영업 1)
```
- 주의: 이 파일은 오전 지시서 "건드리지 말 것"이었다가 오후 팀장 예외로 열렸다. 이번에도 **팀장 확인 후** 손댄다.

### OKR(KpiWidgets.view.tsx OkrBody)
- 범위 칩 [전체][A][B][C][D]: A~D 칩 글자 앞 팀 색 점. 선택된 칩은 지금처럼 흰 바탕(선택 색 규칙 유지).
- 파트 미니 바(963~976줄): 왼쪽 `A` 글자를 **팀 색 글자 배지**로, 막대 색은 지금처럼 달성률 톤(초록 ≥80·노랑 ≥50·빨강) 그대로. 고른 파트는 막대 h-3 유지.
- 미작성 파트 줄(996줄): 빨간 점 → 팀 색 배지 + 빨간 "미작성" 글자(상태는 글자로).
```
 [A] ████████████░░░  80%
 [B] ███████░░░░░░░░  50%
 [C] ███░░░░░░░░░░░░  20%
 [D] ─ 기록 없음
```

### 달성표 펼침(RowDetail)
- 팀별 가로 막대·개인 칩 묶음의 팀 이름(698·713줄)을 같은 팀 색 글자 배지로. 막대·칩 색은 상태색 그대로.
