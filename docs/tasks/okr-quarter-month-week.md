# OKR 기간 구조 바꾸기: 분기 → 월 → 주 (설계안 1차)

- 작성: 기획실 한설계(feature-planner), 2026-10-20
- 근거: 사용자(이민구, CS C파트)가 팀장에게 들은 구조, 팀장 문서 2개("CS팀 4분기 OKR", "CS팀 10월 OKR"), 10월 실행결과 엑셀(팀장 양식), 코드(`src/okr.ts`, `src/OkrHub.tsx`), 라이브 DB 실측(2026-10-20, MCP 읽기 전용)
- 상태: **설계안. 사용자가 확인하고 열린 질문 3개(8절)에 답하면 구현을 시작한다.** 코드와 DB는 아직 하나도 바꾸지 않았다.

## 1. 지금 무엇이 어긋나 있나 (코드·DB 실측)

### 1-1. 표의 열 이름 어긋남. 사용자가 말한 "목표가 병목현상이고, 달성기준이 목표"

팀장 양식은 글 칸이 **세 개**다: **병목현상(글) → 목표(글) → 실행/달성기준(불릿)**. 엑셀 파트 시트 열도 `No · Pillar · 병목현상 · 목표 · 달성기준 · 실제결과 …`로 같다(엑셀 `A파트!C8 / D8 / E8`).

앱은 글 칸이 **두 개뿐**이다.

| 앱 위치 | 지금 하는 일 | 문제 |
|---|---|---|
| `src/okr.ts:39` `OkrGoal = { no, pillar, bottleneck, objective, criteria }` | 필드는 3개 있음 | — |
| `src/okr.ts:315` `defaultGoalTemplate()` → `bottleneck: "병목현상 ${n}"` | **bottleneck 필드에는 "병목현상 1" 같은 꼬리표만** 들어간다 | 병목현상 **글**을 둘 곳이 없다 |
| `src/OkrHub.tsx:45` `shortBottleneck = bottleneckLabel(goals, no).replace("병목현상","병목")` / `:143-148` `BottleneckCell` | "병목" 열은 **위치로 계산한 "병목 1"만** 그린다. bottleneck 필드 값은 화면 어디에도 안 나온다 | 병목현상 글을 적어도 안 보인다 |
| `src/OkrHub.tsx:720` `COLS = ["병목" 58px, "목표" 220, "달성기준" 250, …]` | 파트 시트 열 | 병목현상 글 열이 없다(58px 꼬리표 칸뿐) |
| `src/OkrHub.tsx:904-906` 통합집계 `heads = ["병목","목표", A~D, …]` | 통합집계 열 | 같은 문제 |
| `src/OkrHub.tsx:531` `goalPayload` → okr-assist 에 `objective, criteria`만 보냄 / `supabase/functions/okr-assist/index.ts:62` | AI 보조 | 병목현상 글을 AI가 모른다 |

그래서 팀장 문서를 옮겨 적을 때 글이 **한 칸씩 밀려 들어가기 쉽다**: 병목현상 글이 "목표" 칸에, 목표 글이 "달성기준" 칸에. 사용자가 "목표가 병목현상이고 달성기준이 목표가 돼야 한다"고 한 것이 이 밀림이다.

DB 실측(2026-10-20)으로 확인한 것:
- 모든 달의 `goals[].bottleneck` = `"병목현상 1"`·`"병목현상 2"` 같은 꼬리표뿐(글 없음).
- `2026-10.goals[].objective` = "직무담당제 운영 결과를 점검하고, …정착시킨다" 등 팀장 글로 바뀌어 있음. 그런데 이 글은 10월 실행결과 엑셀의 **병목현상 1**("직무별 담당자와 책임 범위가 정해져 있지 않으면…")과도 **목표 1**("대상 직무의 담당자·책임 범위·목표·완료기준 작성률 100%…")과도 글이 같지 않다. 4분기 OKR 문서의 글로 보인다(열린 질문 Q1).
- `2026-10.goals[].criteria` = **8월 것 그대로**("• 개선 대상 선정(8월 접수 개선항목…)"). 10월 달성기준으로 바뀐 적이 없다.

### 1-2. 판단: 이름만 바꿀까, 값을 옮길까

**JSON 키 이름은 그대로 둔다** (`bottleneck / objective / criteria`). 바꾸는 것은 **뜻과 화면**이다.

| 키 | 새 뜻(팀장 양식) | 화면 열 라벨 |
|---|---|---|
| `bottleneck` | **병목현상 글**. 앞의 "병목현상 N" 꼬리표는 위치로 계산하므로 저장하지 않음. 옛 값이 꼬리표뿐이면(`/^병목현상\s*\d+$/`) 빈 글로 취급 | **병목현상** (위 작은 회색 "병목 1" + 아래 글) |
| `objective` | **목표 글** | **목표** |
| `criteria` | **달성기준 = 팀장 '실행' 불릿을 풀어 쓴 것** | **달성기준(실행)** |

키를 그대로 두는 이유:
1. 49개 기록의 `header.goals`(달성기준 덮어쓰기, 실측 37행에 들어 있음)가 `criteria` 키를 쓴다. 키를 바꾸면 이 칸들을 모두 옮겨야 하고 틀릴 위험이 크다.
2. okr-assist 엣지 함수, `tests/okr.test.ts`, `tests/okrCriteria.test.ts`, `mergeGoals`·`overlayCriteria`가 이 키에 묶여 있다.
3. 8·9월 기록은 objective = 목표, criteria = 달성기준으로 **이미 맞게** 들어 있다(엑셀 8월 양식). 어긋난 곳은 "병목현상 글 칸이 없다"는 것 하나뿐이다.

**값을 옮겨야 하는 곳은 10월 월 OKR 9묶음 하나뿐이다.** 10월 실행결과 엑셀에 10월의 병목현상·목표·달성기준이 9행 모두 들어 있으므로(`1.통합집계 C5:D13`, `A파트 E8:E16`), 그 글로 채운다. 지금 objective에 있는 "직무담당제…" 9개 글은 **백업 표에 남기고**, Q1 답에 따라 분기 OKR 쪽으로 옮긴다. 8·9·11·12월 goals는 건드리지 않는다.

### 1-3. 기간이 어긋난 것

- `okr_cycles.kind` CHECK = `kind in ('month','week')` (실측 `okr_cycles_kind_check`). **분기가 없다.**
- `src/okr.ts:329` `toCycle`: `kind === "week" ? "week" : "month"`. 분기 행이 생기면 옛 코드는 그 행을 **달로 읽는다**(배포 순서 위험, 6절).
- `src/OkrHub.tsx:5-8, 473` 머리 주석에 "분기 안에서는 달마다 같은 목표", "달성기준은 주차마다"라고 적혀 있다. 그래서 분기 목표가 매달·매주 복사된다. `monthDraft`(`:234-240`)는 지난달 goals를 통째로 복사한다(11·12월 = 8월 복사본이 된 원인).
- `MONTH_VIEW_UNTIL = "2026-09"`(`:75`): 10월부터는 '월 종합' 탭이 숨겨져 있다. 그래서 **팀장 양식(월 단위 파트 제출)을 낼 화면이 없다.** 10월 파트종합 행은 실측으로 모두 비어 있다.

## 2. 기간 모델 (새 구조)

### 2-1. okr_cycles 행 종류

| kind | id 규칙 | year / month | week_no | start ~ end | parent_id | goals | 새 열 `direction` |
|---|---|---|---|---|---|---|---|
| `quarter` (신규) | `2026-Q4` (`${y}-Q${q}`) | 2026 / **분기 첫 달(10)**. month CHECK 1..12를 지키려고 | null | 2026-10-01 ~ 2026-12-31 | null | **분기 OKR 9묶음** | 분기 메모(선택) |
| `month` | `2026-10` (지금과 같음) | 2026 / 10 | null | 그 달 1일~말일 | **`2026-Q4`** (10월 이후만) | **월 OKR 9묶음** | **★핵심방향★ 문단** |
| `week` | `2026-10-W1` (지금과 같음) | 2026 / 10 | 1~5 | 월~금 | `2026-10` | `[]` (지금과 같음) | — |

- 분기 = `Math.ceil(month/3)`. 순수 함수 `quarterOf(y,m)`, `quarterCycleId(y,q)`, `monthsOfQuarter(q)`를 `okr.ts`에 더한다.
- 주차 셈법(`okrWorkWeek`, `weekMonthOf`, `okrWeeksInMonth`, `weekIdFor`)은 **바꾸지 않는다.** 11월은 월요일이 5번(11/2·9·16·23·30)이므로 [5주]가 생긴다. 실측 `2026-11-W5`(이민구, 달성기준 9칸)가 그대로 붙는다.
- `goals_origin` 새 열(text, 기본 ''): `''`=예전 그대로, `'copy'`=지난달 복사본(미확정), `'import'`=팀장 문서 붙여넣기, `'manual'`=손으로 확정. 11·12월은 SQL로 `'copy'`를 넣어 "팀장 월 OKR 대기"를 표시한다.

### 2-2. 칸마다 출처 (덮어쓰기 사슬)

| 칸 | 분기 | 월 | 파트 주차(member '') | 파트원 주차 |
|---|---|---|---|---|
| Pillar · 병목현상 · 목표 | **분기 goals** (팀장) | **월 goals** (팀장). 분기와 따로 저장 | 월 것을 읽기만 | 월 것을 읽기만 |
| 달성기준(실행) | 분기 goals.criteria | 월 goals.criteria | 파트가 이 주로 쪼갬 = `header.goals` (**지금 그대로**) | 본인이 쪼갬 = `header.goals` (**지금 그대로**) |
| 실제결과·판정·사유·개선계획·근거 | (집계만) | **파트종합 = 월 report member ''** | 파트 주간 메모(선택) | **본인 주차 기록(지금 그대로)** |

`overlayCriteria`의 사슬은 지금과 **같다**: 월 공통 → 이 주차 파트(member '') → 이 주차 본인. 바뀌는 것은 "월 공통"이 정말 그 달의 월 OKR이라는 점 하나다. 분기 goals는 주차 사슬에 들어가지 않는다.

### 2-3. 분기 OKR과 월 OKR은 따로 저장한다(복사하지 않는다)

- 분기 goals는 분기에 **하나**다. 주차나 달에 복사하지 않는다(사용자: "4분기에 하나여야").
- 월 goals는 팀장 월 OKR로 **채운다**. 아직 없으면(`goals_origin='copy'` 또는 goals 비어 있음) 화면에 분기 OKR을 **읽기 전용**으로 띄우고 "팀장 월 OKR 대기"를 붙인다. 파트원 주차 기록은 계속 쓸 수 있다. 달성기준 사슬의 바탕은 그 달 goals(복사본)이므로 지금과 같이 동작한다.
- 새 달 초안(`monthDraft`)은 **지난달 복사를 멈춘다.** 바탕은 `분기 goals의 Pillar·병목 틀 + 빈 글`, `goals_origin='copy'`로 둔다. 표가 비면 파트원 달성기준 사슬도 비므로 분기 글(병목·목표)은 회색으로 비쳐 보이게만 한다.

## 3. 화면 흐름

### 3-1. 상단 바 (짙은 띠, 지금 자리)

```
[2026년 ▾] [4분기 ▾]   |  [4분기] [10월] [11월] [12월]   · 2026-10-01 ~ 10-31 · 동기화 14:03
```
- `MonthPicker`(1~12월)를 **분기 고르기 + 분기 안 4칩**으로 바꾼다. 다른 분기로 가면 칩이 [3분기][7월][8월][9월]로 바뀐다.
- **주차 칩은 상단에서 뺀다**(파트원 박스 안으로 내려감).
- 처음 열 때: 오늘이 든 분기와 달(10월). 파트원이면 그 파트 탭, 자기 박스, 이번 주 칩까지 자동으로 연다(지금 `openTeam`의 "author면 자기 박스" 규칙을 이어 씀).
- **옛 구조 달(≤ `MONTH_VIEW_UNTIL` "2026-09")**: 3분기에는 분기 행이 없다. [3분기] 칩은 "분기 OKR 없음(옛 구조)"을 띄우고, [8월]·[9월]은 **지금 화면 그대로**(월 종합 + 주차 칩) 연다. 8·9월을 다시 보는 길이 바뀌지 않게 하려는 것이다. 옛 화면은 `LegacyMonth` 경로로 분리하고, 고치지 않고 그대로 둔다.

### 3-2. [4분기]를 고르면

탭은 **통합집계 하나**뿐이다. 파트 탭에는 "월을 고르세요"만 띄운다.

1. **분기 OKR 표**(팀장 편집): Pillar 막대 + 9행. 열 = `병목현상 | 목표 | 달성기준(실행)`. 셀은 RichCell 그대로. 위 단추: [팀장 분기 OKR 붙여넣기] [지난 분기에서 가져오기] [3×3 빈 틀].
2. **분기 진행 표**(읽기): 9행 × (10월 A·B·C·D 판정 | 11월 … | 12월 …). 판정은 월 파트종합 행에서 가져온다. 칸을 누르면 그 달·그 파트로 간다. 조치 필요 파트 수를 달마다 센다.

### 3-3. [10월]을 고르면: 통합집계 탭 (= 엑셀 `1.통합집계`)

- 맨 위 **★ 핵심방향** 한 문단(`direction`, 팀장 편집, RichCell 1칸).
- 파트 카드 4장(지금 그대로: 달성률·판정 n/9·미흡 수). 기준은 **월 파트종합 행**(member '', cycle `2026-10`).
- 표 열은 엑셀 그대로: `No(막대) | 병목현상 | 목표 | A파트 | B파트 | C파트 | D파트 | 조치·확인 필요 파트 | 10월 결과 및 11월 개선계획`.
  - 병목현상·목표 = 월 goals(팀장 편집). 달성기준은 표가 넓어지므로 통합집계에서는 접어 두고, 행을 펼치면 보인다(엑셀 통합집계에도 달성기준 열은 없다).
  - A~D 판정 = 월 파트종합 판정(`actionTeams`·`actionMembers` 그대로). 조치 필요 사람 이름은 **그 달 주차 기록 전체**에서 미흡·미착수인 사람(새 함수 `actionMembersInMonth`).
  - 마지막 열 = `cycle.feedback[no].memo`(지금 '미흡항목 피드백 & 다음 달 개선 방향' 칸). 라벨만 `{m}월 결과 및 {m+1}월 개선계획`으로 바꾼다. ✨초안은 그대로 둔다.
- 단추: [팀장 월 OKR 붙여넣기] [분기 OKR로 시작(병목·목표 복사, 달성기준 빈칸)] [지난달 결과의 개선계획 보기].
- 월 OKR이 없으면(`goals_origin='copy'` 또는 빈 goals): 표 위에 노란 띠 "팀장 11월 OKR 대기, 아래는 4분기 OKR(읽기 전용)". 표는 분기 goals를 회색으로 보여 준다. 판정 열은 그대로 집계한다.

### 3-4. [10월]을 고르면: 파트 탭 A~D (= 엑셀 `A파트` 시트)

사람 박스 줄은 지금과 같다: **[파트 종합] [팀원 집계] | 이민구 박영현 … [＋ 이름]**. 고르는 것에 따라 아래가 달라진다.

**① [파트 종합] = 10월 파트 제출(월 report, member '')**
- 머리: 파트장·작성자·제출일·파트 인원수·제출 항목 수(지금 `header` 그대로).
- 표 열 = 엑셀 파트 시트 그대로:
  `병목현상(읽기) | 목표(읽기) | 달성기준(읽기) | 실제결과 | 종합판정 | 사유 | 개선계획(11월 전략) | 근거자료`
- 노란 칸 5개만 쓴다. 필수 규칙(`needsReasonPlan`)과 미흡 띠는 그대로다.
- **[✨ 주차 합치기]**: 그 달 1~4(5)주 × 파트원 기록을 이 칸에 모은다(새 순수 함수 `mergeMonthActuals(weekReports, no)` → "• 1주 이민구: …"). 판정 제안 = 그 달 모든 판정 중 가장 나쁜 것(`worstOfJudgments` 재사용). 지금의 [합치기]·✨합치기(같은 기간 팀원 → 종합)를 "달 안의 모든 주"로 넓힌 것이다.
- 파트 주간 쪼개기(member '' 주차 기록, 실측 10-W1 D·10-W3 A/C에 달성기준 9칸): 파트 종합 아래 접힌 칸 **[파트 주간 달성기준 1주 2주 3주 4주]**에서 보고 고친다. 팀원 달성기준의 기본값이 되는 사슬은 그대로다.

**② [팀원 집계]**: 지금 `TeamSummary`와 같다. 열은 "파트원 × 그 달 주차 판정"으로 넓힌다. 사람마다 1~4주 판정 점 4개를 찍는다.

**③ 파트원 박스(예: 이민구)** = 그 달을 주차로 쪼갠 본인 기록
- 박스 바로 아래 **주차 칩 [1주 10/5~9] [2주] [3주] [4주(이번주)]** (11월은 [5주]까지). 고르면 `2026-10-Wn`의 본인 report를 연다. **지금 주차 화면 그대로**: 달성기준 덮어쓰기, 결과 5칸, [전주 달성기준 불러오기], [전주 실제결과 불러오기], ✨정리.
- 표 열: `병목현상(읽기, 좁게) | 목표(읽기) | 이번 주 달성기준(쓰기, 월 것이 기본) | 실제결과 | 판정 | 사유 | 개선계획 | 근거자료`.
- 박스 숫자(판정 n/9)는 **고른 주차** 기준이다. 박스에는 달 진행 점 4개(주차별 채움 여부)를 더한다.

### 3-5. 디자인 원칙(지금 것 유지)

설명 문구·이모지 없이, 색은 판정 등급과 노란 입력칸에만 쓴다. 셀 편집(선택 → Del → 더블클릭·Enter), RichCell 색 글자, 열 폭 끌기도 그대로 둔다. `useColWidths` 키는 새 열 수에 맞춰 `okr_cols_team_v2`, `okr_cols_summary_v2`로 바꿔, 옛 폭 저장값이 새 열에 잘못 붙지 않게 한다.

### 5-2. 붙여넣기 파서 `parseOkrPaste(text): { direction?: string; goals: OkrGoal[]; warnings: string[] }` (okr.ts 순수 함수)

받는 꼴 두 가지를 알아본다.

**(가) 팀장 문서 글(스크린샷을 옮겨 적은 글, 카톡·한글 복사)**
```
★ 핵심방향 ★            → direction (다음 머리줄 전까지)
Pillar 1. AI·효율성·비용절감   → 현재 Pillar (pillarIndex 재사용)
병목현상 1  …글…          → 묶음 n.bottleneck
목표 1      …글…          → 묶음 n.objective
실행 1                    → 묶음 n.criteria 시작
· 주간에는 …              → "·"·"•"·"-" 줄은 criteria에 이어 붙임
```
- 머리줄 정규식: `/^\s*(병목\s*현상|목표|실행|달성\s*기준)\s*([1-3])\s*[.:：)]?\s*(.*)$/`, `/^\s*Pillar\s*([1-3])/i`, `/★?\s*핵심\s*방향\s*★?/`.
- 묶음 번호 = (Pillar-1)×3 + N. 머리줄 다음 줄들은 다음 머리줄이 나올 때까지 그 칸에 이어 붙인다.
- 병목·목표·실행의 순서가 뒤섞여도 번호로 맞춘다. 빠진 칸은 `warnings`에 "Pillar 2 병목 3: 실행 없음"으로 남긴다.

**(나) 엑셀 표 복사(탭 구분)**: 10월 실행결과 `1.통합집계`나 `A파트` 시트에서 행을 긁어 붙인 것
- 머리행에서 `병목현상`·`목표`·`달성기준`·`Pillar`·`No` 열 위치를 찾는다. 셀 안 줄바꿈은 엑셀이 `"…"`로 감싸므로 따옴표 CSV 규칙으로 읽는다.
- 병목현상 셀의 "병목현상 1" 꼬리표는 떼어 낸다.

**적용 전 미리보기 모달**: 9행 × (지금 → 새 글)을 보여 주고, 바뀌는 칸만 노랗게 칠한다. 확인을 누르면 goals를 번호(no)대로 바꾼다. **결과 행(rows)·feedback은 번호가 같으므로 그대로 이어진다**(`remapReports` 필요 없음). 9개가 아니면(행 추가·삭제) 지금의 `remapReports` 경로를 그대로 쓴다.
덮기 직전에 옛 goals를 `okr_cycles.goals_prev jsonb`(새 열, 바로 이전 1벌)에 넣는다. 앱은 DDL을 못 하므로 백업 표 대신 이 열을 쓴다. 되돌리기 단추 [직전 목표로 되돌리기]가 이 열을 쓴다.

## 6. SQL: `supabase/okr-quarter.sql` (표다빈 작성 → sql-review → /sql-handoff)

```sql
-- 0) 백업 (지우지 않는 표 복사, 되돌리기 원본)
create table if not exists okr_cycles_bak_20261020 as select * from okr_cycles;
create table if not exists okr_reports_bak_20261020 as select * from okr_reports;
-- (백업 표는 anon·authenticated 권한 회수 + RLS 켬)

-- 1) kind 에 quarter 추가
alter table okr_cycles drop constraint if exists okr_cycles_kind_check;
alter table okr_cycles add constraint okr_cycles_kind_check check (kind in ('quarter','month','week'));

-- 2) 새 열 (모두 기본값 있음. 옛 코드는 이 열을 보내지 않으므로 기본값이 들어감)
alter table okr_cycles add column if not exists direction    text  not null default '';
alter table okr_cycles add column if not exists goals_origin text  not null default '';
alter table okr_cycles add column if not exists goals_prev   jsonb;

-- 3) 표시 정보만 (goals 값은 안 바꿈)
update okr_cycles set goals_origin = 'copy' where id in ('2026-11','2026-12') and kind = 'month';
```
- `parent_id`에는 FK가 있다(`okr_cycles_parent_id_fkey`). Q4 행이 없을 때 month 행의 parent_id를 `'2026-Q4'`로 바꾸면 실패한다. 그래서 SQL에서는 바꾸지 않는다. **앱이 분기 행을 처음 저장할 때 같은 분기의 month 행 parent_id를 함께 저장**한다.
- goals 키 이름 정리 SQL은 **없다**(1-2 판단).

**되돌리기 `supabase/okr-quarter-rollback.sql`**
```sql
update okr_cycles c set parent_id = b.parent_id, goals = b.goals from okr_cycles_bak_20261020 b where b.id = c.id;
delete from okr_cycles where kind = 'quarter';   -- 이 작업이 새로 만든 분기 행만 (분기에는 okr_reports 없음)
alter table okr_cycles drop constraint okr_cycles_kind_check;
alter table okr_cycles add constraint okr_cycles_kind_check check (kind in ('month','week'));
alter table okr_cycles drop column if exists direction, drop column if exists goals_origin, drop column if exists goals_prev;
-- okr_reports 는 이 작업에서 구조·값을 바꾸지 않는다. 필요하면 bak 표에서 행 단위로 복원
```
sql-review에서 delete 줄에 "실행 금지"가 나오면, 그 줄은 사용자 확인 뒤 따로 돌리는 줄로 뺀다.

**배포 순서(중요)**: ① 새 앱 배포(분기 kind를 읽을 줄 앎) → ② SQL 실행 → ③ 앱에서 4분기·10월 붙여넣기. 반대로 하면 옛 앱(PWA 캐시)이 `toCycle`에서 `2026-Q4`를 **달로 읽어**(`okr.ts:329`) 달 목록에 끼고, `monthDraft`의 "지난달" 후보가 될 수 있다. 그래서 SQL에 분기 행 INSERT를 넣지 않는다. 새 앱은 SQL 실행 전에도 동작해야 한다: 새 열이 없으면 400을 감지해(`probeOkrSchema` 방식) 그 열을 빼고 저장하고, "OKR 표를 한 번 더 올려야 합니다" 띠를 띄운다.

### 7-2. 위험

1. **주차 id 셈법**: 상단에서 주차를 빼도 `weekIdFor`(옛 셈법 행 매핑, `OkrHub.tsx:201`)는 그대로 거쳐야 한다. 파트원 박스의 주차 칩도 같은 함수로 id를 만든다. 달 경계 주도 조심해야 한다. 12/1(화)은 11월 5주에 속한다. 그래서 [12월]을 골랐을 때 이번 주 표시는 11월에만 뜨고, 12월의 기본 칩은 1주다.
2. **15초 동기화**: 지금은 열린 cycle 하나와 goalSrc(달)만 다시 읽는다. 새 화면은 분기·달·고른 주차 셋을 본다. 파트종합 [✨주차 합치기]와 팀원 집계에는 그 달 주차 report 전부가 필요하다(`cycle_id=in.(…W1,…W5)` 한 번 조회). 이 조회는 동기화 틱마다 하지 않고, 합치기·집계 화면을 열 때만 한다(속도 기준 `firstoa-field-performance`).
3. **3자 병합**: `mergeCycle`은 title·goals·feedback만 병합한다. `direction` 병합을 더하지 않으면 두 사람이 동시에 고칠 때 한쪽 글이 덮어써진다. 분기 goals 저장도 같은 `saveOkrCycle` 경로를 쓴다.
4. **엑셀식 셀 편집**: `tableCellClick`(`cellNav`)은 표 단위로 동작한다. 병목현상 열이 읽기 칸으로 늘어도 `TD_READ` 클래스를 쓰면 이동 규칙이 유지된다. 열 폭 저장 키는 v2로 바꾼다(3-5).
5. **옛 앱 캐시**: 6절 배포 순서를 따른다. SQL은 열 추가와 CHECK 변경만 하므로 옛 앱은 그대로 동작한다.
6. **권한**: 지금 OKR에는 편집 권한 확인이 없다(`OkrHub.tsx`에 admin/leader 확인 없음, 누구나 통합집계 목표를 고침). 분기·월 OKR도 그대로 두면 파트원이 팀장 글을 실수로 고칠 수 있다(Q3).
