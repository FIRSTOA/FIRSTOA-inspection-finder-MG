# 홈 = CS KPI 현황판 (할 일 C5) — 설계안 1차

- 작성: 기획실 한설계 (2026-10-22 밤, 조사만·코드 0줄·SQL 0줄)
- 요청: 팀장님 — "홈 화면을 CS 의 KPI 가 잘 드러나도록 수치와 %로, 위젯 형식(크기 변경·이동), 점검·PC·블로그 등 KPI 위젯, 정말 CS 만의 현황판처럼"
- 이 문서의 목적: **아침에 사용자·팀장님이 2절 KPI 후보표에서 고르고, 8절 질문에 답한다.** 고르기 전에는 구현을 시작하지 않는다.
- 같은 시각 다른 팀원이 `src/api.ts`·`ServiceReception`·`DeptReception*` 을 고치고 있다. 이 설계는 그 파일들을 **건드리지 않는다**(읽기 재사용만).

## 3. 숫자 신뢰 원칙 (이번 주 확장성 48 vs 45 교훈)

1. **위젯 1개 = 집계 함수 1개.** 위젯은 계산하지 않는다. 숫자는 `src/kpi/kpiCompute.ts` 의 순수 함수 하나가 낸다(입력 = 행 배열 + 범위, 출력 = 값·분모·목표·팀별).
2. **조회 탭·주간현황판과 같은 함수를 쓴다.** 새로 세지 않는다. 확장성 = `countExpansion`, 업무 건수 = `countableEvents`, 미처리 = `countUnhandledTabs`, OKR = `achievementRate`. 화면 안에 묻힌 셈법(Home teamProgress, InspectionReport 미작성, 해피콜 대상)은 **먼저 함수로 꺼내고 원래 화면도 그 함수를 부르게** 바꾼 뒤 위젯이 쓴다("같은 값" 테스트와 같은 커밋).
3. **단위·원본·팀 기준을 위젯에 적는다.** 위젯 아래 한 줄: "기준: 활동 기록 · 기기 대수 · 작성자 팀 · 팀장 제외 · 재전송 1건" (확장성의 `EXPANSION_BASIS_TEXT` 방식).
4. **위젯을 누르면 같은 숫자의 목록으로 간다.** 점검 → 주간현황판 [팀 현황] 같은 기간·같은 팀, 확장성 → 조회 탭 PC 확장성 같은 기간. 숫자가 다르면 그 자체가 버그다.
5. **"0"과 "못 읽음"을 구분한다.** 실패 = "—" + [다시] + 마지막 성공 값(시각 표시). 기록 없음 = "0" + "기록 없음". 원본 표가 아직 없음(misu_visits 등) = "준비 중".
6. **테스트**: `tests/kpiCompute.test.ts` — 같은 고정 행 배열을 KPI 함수와 기존 화면 함수(TeamRanking METRICS·countExpansion·countUnhandledTabs)에 넣어 같은 값인지. 기간 경계(KST 월요일 00시, 월말, 분기말) 포함.
7. **목표값은 코드에 박지 않는다.** 기본값 = OKR 문서에서 옮긴 상수, `app_config` 키 `KPI_TARGETS`(JSON)가 있으면 덮는다(CostTile 단가 덮어쓰기와 같은 방식, SQL 불필요). 11·12월 숫자가 바뀌면 관리 탭에서 고친다.
8. **팀 기준 하나**: "작성자 명단 팀, 팀장 제외, 확장성 PC 만 지역 칸 우선"(지금 팀 현황·순위표 규칙). 홈의 "지역 칸 첫 글자" 셈법은 버린다(Q3).

### 4-1. 위젯 틀 5가지 (ui-designer 가 그린다)

| 틀 | 모양 | 쓰는 KPI 예 | 최소 크기 |
|---|---|---|---|
| 숫자 카드 | 큰 숫자 + 단위 + "지난주 대비 ▲12%" + 기준 한 줄 | K1 K3 K4 K16 K17 | 1x1 |

## 7. 위험

- **숫자가 지금 홈과 달라진다.** 원본을 activity_events(대수)로 바꾸면 "오늘 현장 기록"이 지금 숫자와 다르다 → 바뀐 날 패치노트와 위젯 기준 줄로 알린다.
- activity_events 는 FIELD 로 보낸 것만 있다. 시트에 직접 적은 점검·AS 는 빠진다(확장성에서 확인된 패턴 — 확장성은 시트 미러 원본으로 해결). 점검·AS 도 그런지 표다빈이 실측해야 한다. 크면 K1·K3 원본을 jeomgeom·as_records 로 바꾸고 순위표도 같이 바꿔야 한다(그때는 debugger·별도 지시서).
- 개인 순위·미달을 모든 직원이 보는 홈에 띄우면 압박·민원 가능 → Q10.
- "개인 주 5곳" 목표는 공휴일·휴가 조정 규칙이 OKR 에 있다 — 1단계는 조정 없이(또는 위젯 제외), 조정은 3단계.
- 홈 조회 수: 지금 60초마다 13개 조회 + 전송 현황판 15초. 로더 묶기·접힘 폴링 멈춤으로 오히려 줄이는 게 목표 — 검수아가 전후 비교.
- misu_visits 미실행 상태에서 K14 를 켜면 404 → "준비 중" 처리 필수.
- OKR 대상은 A~D(E 제외), 점검·확장성은 A~E — 같은 판에서 팀 줄 수가 달라 보일 수 있다(위젯마다 기준 줄로 설명).
- 네트워크 끊김: 마지막 성공 값을 sessionStorage 에 두고 "N분 전 값" 표시. 같은 화면 두 번 여는 중복 조회는 지금 useTelemetry 의 busy 막기 방식 그대로.
