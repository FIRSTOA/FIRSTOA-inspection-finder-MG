# 접수리스트에 시트에만 적힌 접수도 보이기 (2026-10-28, 기획실 한설계)

> 조사·설계만. 코드 0 · SQL 0(1단계). 실측: 2026-10-28 저녁 접수 문서 1QRl… 공개 CSV, Supabase REST anon GET.

## 0. 사용자 요청(2026-10-28)
"접수리스트에 **양방향 동기화**로 이런 것도 가능한가? 저번 주 영업·경영·운영 접수는 시트에 새로 만들어서 웹앱 접수리스트엔 없더라. **싹 다 나오게**. CS 접수·IT·원격도 없을 텐데 필요하겠다. **이번 달 것만, 이제부터 쌓아 나가자**. 가끔 웹으로 접수 안 하고 시트에 적는 사람들이 있어서 **누락 방지**."

## 1. 한 줄 목표와 쓰는 사람
- 서비스접수 › 오른쪽 **접수리스트**가 "앱 접수 ∪ 시트에만 적힌 접수(2026-10-01부터)"를 한 목록으로 보여 준다. 시트 줄은 "시트" 칩을 단다.
- 쓰는 사람: CS팀 접수 담당(지경민·김광태·신동원 등)·부파트장, 경영·영업 담당. **PC 위주**(접수 화면), 폰은 보기만.
- "양방향"의 범위: 시트 → 앱 = 읽어서 보여 줌. 앱 → 시트 = 이미 있는 statusOnly(상태·처리자 칸만)뿐. 시트 행의 다른 칸을 앱에서 고치지 않는다.

결정적 사실 다섯
1. **부서 접수는 여전히 거의 다 시트에만 있다**(영업 317·경영 95). 원격·IT도 앱 접수는 월 4건뿐이고 약 1,325행이 시트에만 있다. CS 접수는 3건 중 1건이 시트에만 있다(신동원 39·김수인 24·김정식 23·지경민 20 …).
2. **원격 탭과 AS접수용 탭은 이번 달 행만 있다**(년월 전부 2610, 순번 1부터). 달이 바뀌면 지난달 행이 탭에서 사라진다(옮겨 가는 곳 미확인, 10-22 설계서 reception-unhandled-sheet-and-dept-search.md 3절과 같음). → 시트를 그때그때 읽기만 하면 **11월 1일에 10월 원격·IT·CS 시트 행이 목록에서 사라진다.** "이제부터 쌓아 나가자"를 지키려면 어딘가에 남겨야 한다(4절 2단계).
3. 영업·경영 탭은 몇 년치가 쌓여 있다(영업 5,956행·경영 1,788행). 경영 C열(년월)은 1,787행이 비어 있어 B열 "10월 29일"만 보면 **2025년 10월(136행)도 섞인다** → 엣지 inferMissingYears(아래→위 연도 추정)를 반드시 거친다.
4. CS 앱 접수는 sheet_row 를 거의 안 남긴다(476건 중 3건). 시트 잡 _dupKey 도 잡 id 라 접수 id 로 못 돌린다 → CS 잇기는 **(접수일, 퍼스트순 F열 = first_no/lease_no, 접수자 E열)** 일치로 한다(실측 488/749 이어짐, 남는 DB 6건).
5. 원격 탭은 접수자 열(J, 10)이 있는데 지금 엣지 SHEET_LAYOUTS.remote 에 authorCol 이 없다(접수자를 빈칸으로 돌려줌).

## 3. 두 방식 비교와 추천

| 기준 | (A) 가상 표시 — 엣지가 시트 행을 돌려주고 화면이 합침 | (B) DB 적재 — 시트 행을 service_receptions 에 넣음 |
|---|---|---|
| 중복·연결 | 엣지가 이미 하는 linkRows(영업·경영 잡 sheet_row+접수자, 원격 sheet_row+상호) + CS 새 규칙 하나. 이어진 시트 행은 숨기고 앱 행을 보임 | 넣을 때 같은 잇기가 필요하고, 잘못 이으면 **영구 중복 행**. 시트 행 밀림·삭제 때 DB 행이 고아로 남음 |
| 완료 행 | 그대로 보임(시트 상태 그대로) | 넣은 뒤 상태 동기화(heal)를 상시 돌려야 함 |
| 숫자 통일 | 접수리스트만 바뀜. 홈 미처리·현황판(영업·경영·원격·IT = 시트 열린 행, CS = 일정 기준)은 **그대로** | service_receptions 를 읽는 모든 곳(홈 미처리·현황판·통합검색 360·KPI·주간 순위·자동 일정·카톡 후속 글·삭제 연쇄)에 월 2,000행 유입 → **전 화면 숫자 회귀** |
| 개인정보 | 엣지가 이미 가림(maskPhones·전화 열 제외) | 가린 값이 접수 표 정본이 됨 |
| 기존 규칙 | 엣지 1개 확장 + 프런트 합치기. SQL 0 | 출처 칸을 두려면 기존 표 변경(작업 규칙 2 위반) 또는 remote_meta 에 숨김. 크론 SQL·sql-review 필요 |
| 성능 | 일일 약 100행 · 월 약 2,000행. 60초 캐시 공유 | 조회 빠름, 쓰기·동기화 비용 |
| 쌓기(달 바뀜) | **못 함** — 원격·CS 탭이 매달 비워짐 | 됨 |
| 공통 한계 | 시트 줄엔 사진·메모·후속 카톡 글·일정 연결이 없음 | 같음 |

**추천 = A 를 지금(1단계) + 달 바뀜 대비 "시트 행 보관 표"(2단계, 접수 표와 분리된 읽기 전용 거울).**
- 팀장 1차 의견(A가 안전하고 빠름)에 동의. B(접수 표 적재)는 하지 않는다 — 숫자 회귀 범위가 너무 넓고, 이득(쌓기)은 별도 보관 표로 얻는다.
- 2단계 보관 표는 접수 표를 읽는 화면들에 영향이 없다. 화면은 1단계와 같은 합치기 함수를 쓰고 원본만 "엣지(이번 달)" ↔ "보관 표(지난달)"로 바꾼다.
- **기한: 10월 원격·IT·CS 시트 행을 남기려면 2단계가 10월 31일 밤 전에 한 번 돌아야 한다**(Q2). 1단계만 하면 11월부터는 10월 원격·CS 시트 줄이 안 보인다(영업·경영은 탭에 남아 계속 보임).

## 4. 데이터 설계

### 1단계(SQL 0) — 엣지 reception-sheet-open 에 "목록 모드" 추가
- 요청: `{ list: { from: "YYYY-MM-DD", to: "YYYY-MM-DD" } }`(접수리스트 기간 칩 범위). 기존 `{}`(미처리, 홈 60초 폴링)·`{ row }`(상세)는 그대로.
- 응답: `{ ok, rows: SheetListRow[], noDate, fetchedAt, errors, okSources, cached }`
  - SheetListRow = 기존 SheetOpenRow 모양 + `cls` 에 "done" 허용(copier 는 "record") + `source` 에 "copier" + `time?`(접수시간: CS D열·원격 D열). `content` 는 싣지 않는다(크기 — 상세는 row 상세로).
  - 조건: `date >= SHEET_LIST_START("2026-10-01")` 그리고 from ≤ date ≤ to. **이어진 행(receptionId 있음)은 빼고 보낸다**(앱 행이 대신 보임). 날짜를 못 읽은 행은 개수(noDate)만.
  - 범위는 최대 92일로 자른다(공개 호출).
- 캐시: 지금 compute() 의 "파싱된 전체 행 + links" 를 60초 캐시 하나로 두고, 미처리 응답과 목록 응답이 **같은 시트 읽기 1회**를 나눠 쓴다(Sheets API 호출 늘지 않음). 캐시 키는 시각만, 범위 거르기는 캐시 뒤에서.
- 새 탭 배치 `SHEET_LAYOUTS.copier`(10-28 CSV 머리 실측): gid 1181394897, firstRow 5, headerRow 5, dataStart 8, 읽기 A5:T 와 BD5:BD 두 범위(56열 전부 읽지 않음), markerCols [2,5,6], seqCol 1(순), dateCol 2(날짜), yymmCol 3(년월), timeCol 4(접수시간), authorCol 5(접수자), firstNoCol 6(퍼스트순), vendorCol 8(업체명), fieldCol 10(접수분야), 제목 19, summaryCol 20(내용), statusCol 56(머리 "처리완료"). 3·4행(머리 사본·최신 미리보기 행)은 firstRow 5 라 읽지 않는다. 상세(detailLastCol)는 AV(48)까지, 전화 열(일반전화·전화번호)은 기존 PRIVATE_HEADER 로 빠짐.
  - 머리 검증: copier 는 B5 "날짜"·E5 "접수자"·F5 "퍼스트순"·T5 "내용" 네 칸(지금 headerError 는 상태 열·한조 열만 본다 → copier 전용 검사). 다르면 그 탭만 errors.
  - copier 상태: BD 칸은 상태가 아니라 앱이 적는 메모다. **copier 시트 행은 cls = "record"**(Q4). openRowsOf(홈 미처리)에는 **넣지 않는다**(CS 접수 = 일정 기준 유지).
- `SHEET_LAYOUTS.remote` 에 `authorCol: 10`(J 접수자)·`timeCol: 4` 추가. 미처리 숫자 영향 없음(빈 접수자 칸이 채워질 뿐).
- CS 잇기 `linkCopierRows(rows, dbCopier)`(state.ts 새 순수 함수): 이번 달 service_receptions(type=복합기 AS, receipt_date ≥ 이번 달 1일, deleted=false; select id,receipt_date,first_no,lease_no,author,vendor; 10월 476행) 와 ① (날짜, 퍼스트순, 접수자) 1:1 소비 → ② (날짜, 퍼스트순) 1:1 → ③ 퍼스트순 빈 행(신규 거래처)은 (날짜, 접수자, 상호 앞 6자). 읽기만.
- 응답 크기(10월 실측 추정, content 없음, 한 줄 약 280B): 일일 약 100행 ≈ 30KB · 주간 ≈ 150KB · 월간 약 2,000행 ≈ 560KB(gzip 약 100KB). 분기 칩은 10-01 이후만이라 지금은 월간과 같음. 기존 미처리 응답(gzip 약 100KB)은 그대로. 목록 호출은 접수리스트가 보일 때만(기간 바뀜·새로고침·60초 갱신), 홈은 부르지 않는다.

### 2단계(SQL 1개, db-schema → sql-review → 사용자 실행) — 시트 행 보관 표 `reception_sheet_rows`
- 한 행 = 시트 한 접수: source(sales|mgmt|remote|copier) · month(YYYY-MM) · seq(시트 A열 순번) · sheet_row · kind · receipt_date · receipt_time · author · handler · state · cls · vendor · field · region · summary(가린 40자) · content(가린 600자) · reception_id(이어진 앱 접수, 없으면 null) · first_seen_at · last_seen_at · gone_at(시트에서 사라진 시각).
- 고유 키 (source, month, seq) upsert. 순번이 빈 행은 (source, month, receipt_date, author, vendor 앞 6자) 해시. **통째 교체·삭제 금지**(misu 사건 교훈) — 사라진 행은 gone_at 만 찍는다. 단 달이 바뀌어 탭이 비워진 것(그 달 행이 한꺼번에 사라짐)은 gone_at 을 찍지 않는다.
- 적재: 엣지 `{ snapshot: true }` 를 pg_cron 매시간(ops.call_edge, 카톡 발송 아님) + 말일 23:30. service role 로 upsert.
- 권한: RLS 켬, anon select 만(가린 값만), insert/update 는 service role(엣지)만.
- 화면: 범위가 이번 달 이전이면 보관 표에서, 이번 달은 엣지에서 읽어 같은 합치기 함수로.

## 5. 화면 흐름
1. 서비스접수 › 오른쪽 [접수리스트] — 지금처럼 앱 접수를 읽고, 동시에 엣지 목록 모드(기간 칩 범위)를 부른다. 엣지가 늦거나 실패하면 앱 접수만 먼저 보이고 맨 위 회색 한 줄 "시트 접수를 못 읽음 — 앱 접수만 표시"(숫자를 0으로 만들지 않음). 스위치 RECEPTION_SHEET_OPEN_ENABLED 가 꺼져 있으면 부르지 않는다(지금 화면 그대로).
2. 시트 줄: 앱 줄과 같은 줄 모양. 시각 자리 = 시트 접수시간(없으면 "--:--"), 종류 점 옆 **"시트" 칩**(회색 테두리), 업체 = 시트 상호, 둘째 줄 = 내용 40자(CS 는 제목 — 내용), 셋째 줄 = **접수자(영업·경영·CS E열 · 원격 J열)** · 지역 · 처리자. 오른쪽 상태 = 시트 상태(접수/진행중/완료, 보류는 진행중 칸에 "보류" 글자) — CS 시트 줄은 "기록".
3. 위 필터: 종류 칩·상태 칩 숫자에 시트 줄 포함(예 "원격이관 74"). 기간 줄 "· N건" 옆에 "(앱 n · 시트 m)". 정렬은 날짜·시각 내림차순으로 앱 줄과 섞음.
4. 시트 줄을 누르면 펼침: 엣지 row 상세(열 전부, 전화 열 제외)를 불러 표시. 안내 한 줄 "시트에서 적은 접수 — 사진·메모·카톡 후속 글·일정 연결은 없습니다". [시트에서 열기](sheetRowUrl). 완료 행도 상세가 열려야 하므로 엣지 상세에 allowDone 추가(지금은 완료면 409).
5. 처리 단추: 영업·경영 = [완료][보류][배정], 원격·IT = [완료][배정](보류 없음) — 기존 UnhandledActionBar·statusOnly 그대로, **열린 줄에서만**. 완료 줄·CS 시트 줄은 단추 없음. 순번 칸이 빈 줄(영업 A열 배열 수식 사고 때)은 단추를 숨기고 상세만.
6. (2차, Q5) CS 시트 줄 [앱 접수로 가져오기] — 접수 폼에 퍼스트순·업체·내용·접수자를 미리 채워 열기. 저장하면 시트 기입은 건너뜀(이미 있음), 일정·카톡만. 1단계 범위 밖.
7. 아래 "접수자별 처리" 카드: 앱+시트 합산(Q3), 머리 "(시트 m 포함)".

## 7. 테스트 표본
- copier 파싱: 4행(미리보기 "748 / 10월 28일")·3행(머리 사본) 무시, 8행 "1 / 10월 1일 / 2610 / 9:06 / 김광태 / 19655" → date 2026-10-01 · time 09:06 · author 김광태 · seq 1 · cls record.
- copier 머리 변경: F5 가 "퍼스트순" 아니면 errors 1줄, 다른 탭 행은 그대로.
- 경영 연도 추정: 아래 블록 "10월 1일"~"10월 28일"(C 빈) + 위 "10월 29~31일" → 위 것은 2025-10 → 목록(2026-10-01~)에서 빠짐.
- linkCopierRows: (날짜·퍼스트순·접수자) 같은 시트 행 2개 + DB 1건 → 1개만 이어짐. 퍼스트순 같고 접수자 다름 → 2차 규칙. 퍼스트순 빈 신규 → 상호 앞 6자.
- listRowsOf: 이어진 행 제외, 2026-09-30 제외, 미래 날짜(원격 "10월 30일" 1행 실측) → noDate.
- mergeListWithSheet: 앱 3 + 시트 5 → 8줄, 종류 칩 숫자, 접수자별 합.
- 회귀: openRowsOf 결과에 copier 0행, 기존 미처리 표본 숫자 불변, remote authorCol 추가 뒤에도 linkRows 결과 불변.

## 8. 위험
- **R1 달 바뀜(원격·CS 탭 비움)** — 2단계 없으면 지난달 시트 줄 소실. 기한 10-31 밤.
- R2 행 밀림·삭제: sheetRow 가 바뀜 → 상세·statusOnly 는 이미 순번(+상호) 확인으로 막음(409). 목록은 60초마다 다시 읽어 맞춰짐. 보관 표 키는 행 번호가 아니라 (source, month, seq).
- R3 순번 칸 수식: 영업 A열 순번은 머리 ARRAYFORMULA(10-27 #REF! 사고). 순번이 비면 단추 숨김·상세만.
- R4 연도 추정(경영 C열 빈칸): 범위 시작 2026-10-01 고정, inferMissingYears 결과만 믿음. 날짜 모름은 목록 밖 개수로.
- R5 머리 바뀜: 탭별 머리 검증 실패 시 그 탭만 빠지고 안내 줄. 조용히 틀리지 않음.
- R6 목록이 길어짐: 일일 약 25줄 → 약 120줄(원격·IT 하루 약 70). 각 탭은 그 종류 칩이 기본이라 탭 안에서는 그 종류만.
- R7 공개 호출 엣지: 캐시 우회 옵션 없음, 범위 최대 92일, 가림 유지. 키맨·업체담당자 이름은 보임(지금 상세와 같음).
- R8 CS 잇기 오탐: 같은 날 같은 퍼스트순·같은 접수자 재접수 2건은 1:1 소비라 하나만 이어지고 남는 줄은 "시트"로 보임(누락보다 나음).
- R9 시트 읽기 양: copier 두 범위 추가(약 750행×21열 + 1열) — batchGet 1회 안이라 호출 수 그대로, 응답 약 +0.4MB(엣지 안에서만).

## 9. 열린 질문(사용자에게 한 번에)
- **Q1** 운영지원은 시트가 없어 이번엔 뺍니다. 운영 접수를 따로 적는 시트(또는 방)가 있나요?
- **Q2** 원격·CS(AS접수용) 탭은 달이 바뀌면 지난달 행이 없어집니다. (가) 2단계 보관 표를 10월 31일 전에 넣는다(SQL 1개 실행 필요) (나) 1단계만 하고 11월부터 쌓는다(10월 원격·CS 시트 줄은 11월에 사라짐). 지난달 행이 옮겨 가는 보관 문서가 있으면 알려 주세요.
- **Q3** 접수자별 처리 카드에 시트 줄을 넣으면 원격 접수 담당(지경민 10월 509건 등) 숫자가 크게 늘어납니다. 합산 / "앱만·전체" 전환 중 어느 쪽?
- **Q4** CS 시트 줄은 시트에 상태 칸이 없습니다(BD "처리완료"는 메모). "기록"(상태 없음)으로 둘까요, BD 에 "완료"가 있으면 완료·없으면 접수로 볼까요? (접수로 보면 10월 접수 칩이 약 260 늘어남)
- **Q5** CS 시트 줄에 [앱 접수로 가져오기](일정·카톡을 위해 앱 접수로 승격)를 2차로 넣을까요?
- **Q6** 원격·IT 시트 줄이 하루 약 70줄입니다. 접수리스트 '전체' 칩에서도 보일까요, 원격·IT 칩에서만 보일까요?
