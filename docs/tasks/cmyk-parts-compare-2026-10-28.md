| 재계약 준비 | src/recontract/(이카운트 대장 분석·활용률·추천 플랜) | 재계약 때 "교체 임박 부품" 근거 |
| 이메일 카운터(대기) | AGENTS.md "이메일 카운터" — 대표 승인·IMAP 대기 | 매일 카운터 → 시계열이 촘촘해짐 |

단계안(제안, 승인 전):
1. **수명표 옮기기(표 1장)** — `parts_life`(브랜드·기종·품목·수명매수·출처·기준일) + `model_alias`(vendor_info 모델명 표기 ↔ 수명표 기종, 예 "D450/470 공용"·"(마블2)" 별명). 35기종 그림 → 손입력 또는 그림 글자 인식 후 사람 확인. 손입력 하루 이내 분량.
2. **"교체 예정" 계산(읽기만)** — 기번마다: 마지막 교체 시점 카운터(교체 사건 + 그 무렵 점검 매수) → 지금 카운터 → 사용 매수 / 수명 = 사용률. 하루 평균 출력으로 남은 일수 → 예정일. 토너는 매수보다 **잔량%** 가 정확하므로 잔량 우선.
   - 표시 후보: 점검 양식 기기 줄 옆 "퓨저 82%·드럼 95%" 알약, 워킨맵 배지, 재계약 준비 화면 "교체 임박 부품" 칸, 부품 신청 때 "이 기기 드럼 수명 40%인데 교체?" 확인.
3. **실제 수명 보정(ERP 항목 3)** — 교체 사건 사이 실제 매수 / 표 매수 = 보정 계수(기종·업체 단위). 쌓이면 "우리 고객 기준 실제 수명표"가 된다. 조기 고장(표의 50% 미만에 교체) 목록 = 불량·사용 환경 신호.
4. **재고와 연결** — 30일 안에 바꿀 부품 수(2의 합) vs StockBoard/부품실재고 시트 수량 → 부족 경고.

막히는 곳(확인 필요):
- 교체 사건이 **기번 단위로 이어지는지**: supply_requests 는 업체·품목 단위가 많다(한 업체 여러 대면 어느 기기인지 모름).
- 점검 매수 빈도: 점검 주기(월/분기)만큼만 점이 찍힌다. 이메일 카운터가 들어오면 해결.
- 수명표 기종이 35개뿐 — 우리 임대리스트 기종 중 몇 %를 덮는지 vendor_info 모델명 분포로 먼저 재 봐야 한다(이번 조사에서는 안 셈).

## C. CMYK 포털(cmyk.oqupie.com/portal/3342) vs FIELD

### C-1. 열어 본 결과 — **내용을 읽지 못했다**

- 주소는 응답 200 이지만 본문은 빈 껍데기(`<div id="root"></div>` + 자바스크립트 1개, 1,092바이트)다. 화면은 브라우저에서 자바스크립트가 그린다 → WebFetch 로는 메뉴·글이 하나도 안 보인다.
- 껍데기의 스크립트 주소 `cdn.oqupie.com/portal/...` 로 보아 **오큐피(OQUPIE)** 라는 고객지원(헬프데스크) 서비스의 **고객 포털** 이다. 3342 는 그 회사의 포털 번호.
- 웹 검색("oqupie cmyk 포털", "cmyk.oqupie.com", "씨엠와이케이 복합기")에도 이 포털을 설명한 글이 없었다. CMYK 가 어느 회사인지(동종 임대업체? 사내 다른 부서?)도 확인 못 했다.
- 로그인 벽인지는 알 수 없다(그리기 전 단계에서 막힘).

→ **아래 C-2~C-4 는 오큐피 포털의 일반 기능(공식 안내 support.oqupie.com 기준)으로 짐작한 것이라 전부 "추정"이다.** 정확히 하려면 사용자가 그 포털 첫 화면·메뉴를 캡처해 주거나, 대표님 논의 때 본 기능 목록을 적어 주면 이 절을 다시 쓴다.

오큐피 공식 안내에서 확인된 것: 이메일·SNS 등 여러 경로 문의를 **티켓** 하나로 모음, 담당자 배정·우선순위·상태·문의 유형 필터, 저장된 답변, 내부 메모, 고객 프로필에 지난 문의 이력, 고객 포털·모바일 SDK 로 고객 정보 수집.

**CMYK(포털형)가 더 나은 점(추정)**
- 고객이 **스스로** 접수하고 진행을 본다 → "언제 와요?" 전화가 줄고, 접수 누락이 구조적으로 없다.
- 문의가 처음부터 정해진 칸(유형·기기·사진)으로 들어와 직원이 다시 옮겨 적지 않는다.
- 상용 서비스라 유지보수·보안·다국어·통계 화면을 우리가 만들 필요가 없다.

**FIELD 가 빠뜨린 것**
- 고객 쪽 입구(셀프 접수·상태 조회·FAQ 연결)가 없다 — 모든 일이 직원 손을 거친다.
- 고객 답변 틀·만족도 응답 수집이 없다.
- 고객 리포트에서 '전송완료'(=AS 방에 보냄, 90일 314건)를 "처리 완료"로 보여 주는 정의 불일치가 아직 남아 있다(review-2026-10-27.md) — 고객에게 상태를 보여 주려면 이것부터 맞춰야 한다.

**FIELD 가 더 나은 점**
- 현장(점검·AS·물류)·카운터·부품·재계약·워킨맵·고객 리포트까지 **업무 전체**가 이어져 있다. 헬프데스크는 "문의 창구"까지만이다.

### C-4. ERP 반영 검토 때 가져올 기능 후보

1. **고객 셀프 접수 폼**(기기 QR → 업체·기번 자동 → 유형·사진) → `service_receptions` 에 바로. 보류 중인 "고객용 QR AS 접수"를 되살리는 것. 스팸·장난 접수 막기(기번 확인) 필요.
2. **접수 상태 조회 링크**(문자로 받은 링크에서 접수·배정·방문 예정·완료만 보기, 로그인 없이 한 건 한정 토큰).
3. **고객 FAQ 연결** — 기존 고객용 사용설명서 사이트 글을 접수 폼 옆에 "먼저 해 보세요"로.
4. **답변 틀** — 자주 쓰는 고객 회신 문구 저장.
5. **설치후기·홍보 참여 신청 폼**(ERP 항목 5) — 셀프 접수와 같은 틀로 만들면 한 번에 해결.

대안: 직접 만들지 않고 오큐피 같은 상용 포털을 쓰고 FIELD 와 연동(포털 티켓 → service_receptions)도 가능. 비용·연동 방식(웹훅 지원 여부)은 확인 필요.

다음에 필요한 것: CMYK 포털 화면 캡처 또는 메뉴 목록(사용자) → C 절 "추정" 지우고 다시 쓰기.
