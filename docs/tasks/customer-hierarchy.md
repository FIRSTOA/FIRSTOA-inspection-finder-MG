# 거래처 3단 구조 (업체 › 지점·현장 › 기기) — 구상 메모

작성: 2026-10-21 (사용자 구상 + 팀장 클로드 DB 실측). **상태: 보류 — 나중에 꺼내서 진행.**
**2026-10-31 실행 계획으로 전환 → docs/tasks/customer-hierarchy-plan-2026-10-31.md** (이 문서는 구상·실측 기록으로 보존).
방향: "퍼스트전산 하나의 장부 + 부서별 창 + 그 위에 검색·AI" (ERP+AI 로의 DB 통합). 어떤 키로 찾아도 같은 업체로 모이게.

## 1. 구조

```
대분류  업체       예) 세안이엔씨          ← 사업자번호 10자리로 묶는다(이름은 별칭)
중분류  지점·현장   예) O현장 / OO본점      ← 임대리스트 5자리 코드 (주소 1개, 지역 필터)
소분류  기기       순번(마스터)            ← 자산기번(알파벳1+숫자4)은 따라붙는 별명
```

- **마스터는 순번.** 기기 1대 = 순번 1개. 순번이 지점(5자리)을 따라가고, 지점이 업체(10자리)를 따라간다.
- **자산기번은 화면·검색용.** 현장 CS 직원은 순번이 아니라 자산기번을 쓴다 → 화면에는 자산기번을 크게, 저장은 순번으로. 자산기번이 바뀌면 순번에 "언제부터 이 기번" 이력 한 줄.
- **주소·담당자·연락처는 지점의 옵션 속성.** 바뀌어도 기기는 그대로. 기기를 다른 지점으로 옮기면 순번이 새 지점을 따라가고 이동 기록만 남김.
- **업체명 글자로 묶지 않는다.** "세안이엔씨 / (주)세안이엔씨 / 세안E&C" 가 갈라짐 → 대분류 키는 사업자번호, 이름은 별칭(vendor_master.aliases 류).

## 3. 비어 있는 것 = 할 일

1. **지점(5자리) → 업체(10자리) 연결표** 만들기 (핵심, 이것 하나가 대분류).
   - 재료: 순번 → 기번(vendor_info 기번/시리얼) → `lease_ident_code` → 10자리. 지점 안 기기들의 10자리가 하나로 모이면 자동 연결.
   - 먼저 **자동 연결 비율** 조회 → 못 이은 지점 / 기기마다 10자리가 갈리는 지점만 목록으로 뽑아 사람이 맞춤.
   - 새 표 예: `site_company(site_code 5자리 PK, company_code 10자리, method auto|manual, updated_at)` — SQL 은 /sql-handoff (새 표 grant 명시).
2. **자산기번 이력**: 순번별 자산기번 변경 기록(현재 값 + 언제부터). 지금은 vendor_info 스냅샷만 있음.
3. **데이터 정리**: 순번 없는 행 ~350, 코드 칸 메모 값 ~678종.
4. **통합 검색 360 연결**: 업체명·10자리·5자리·순번·자산기번 무엇을 넣어도 같은 업체로 모이게(지금은 두 코드 체계가 따로 수집됨 — 메모리 firstoa-search360).
5. 이후: 서비스접수·점검·AS·부서 접수가 순번/지점/업체 키를 같이 저장 → 업체 단위 이력·미처리·AI 질문("이 업체 최근 3개월 AS·초과·계약 만료").

## 4. 원칙

- 남의 데이터는 옮기지 않고 "보는 창"으로 잇는다(IT 프로젝트 철회 사건, 2026-10-03).
- DB 쓰기는 사용자가 SQL Editor 에서(/sql-handoff). 자동 REST 이동·삭제 금지.

## 6. 정정 — 사용자 확인(2026-10-23): "5자리"는 A열 순이 아니라 U열 "코드"였다

- 사용자가 말한 기기 번호는 **임대리스트 A열 "순"**(vendor_info."순번", 기기 1대 = 1개). 이 문서 1~5절의 "지점 5자리"는 **U열 "코드"**(vendor_info."코드")로, 다른 번호다.
- U열 코드는 같은 코드 안에 서로 다른 업체가 섞이는 경우가 있다(예: 22082 — 알스퀘어디자인 기기와 아이지엠아이디 기기). 거래처 구조의 기준으로 쓰지 않는다(참고 칸).
- 바뀐 구조:
  - 대분류 업체 = 거래처 코드(사업자번호 10자리, `_raw->>'거래처 코드'`), 이름은 별칭
  - 중분류 현장·부서 = Q열 "부서명/현장명"(+ 주소) — vendor_info."부서명" 생성 컬럼(supabase/vendor-info-dept.sql)
  - 소분류 기기 = A열 순(마스터), 자산기번은 별명
  - 기본 표시는 임대여부 "임대중"만(임대중 10,881대 · 임대종료 12,071대 · 소송 336대, 2026-10-23), 종료 기기는 이력으로 접기
- 5절의 연결 실측(88.3%)은 U열 기준이라 다시 센다. supabase/site-company.sql 초안도 이 기준으로 다시 쓴다(실행 금지).
