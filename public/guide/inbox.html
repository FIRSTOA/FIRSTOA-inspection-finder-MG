공지·요청 길잡이

사이드바 소식 › 공지·요청입니다. "사람이 나에게 보낸 것"을 한곳에 모았습니다 — 공지는 읽으면 끝, 부서 요청은 처리해야 끝. 누가 읽었는지, 누가 처리 중인지가 전부 보이고, 새 글은 사이드바 빨간 숫자와 웹푸시로 알려 줍니다. 이 화면은 네이버 캘린더·카톡방·시트와는 연결되지 않습니다.

시작하기 전에 — 사이드바 빨간 숫자의 뜻

사이드바 "공지·요청" 옆 빨간 숫자 = 안 읽은 공지 + 나에게 온 대기 요청 + 내가 보낸 요청의 진행 소식. 세 가지가 합쳐진 값이라 이 화면에 들어오면 상태줄에서 각각 몇 건인지 나눠 보여 줍니다.

"나에게 온 것"의 기준대상이 전체면 모두, 팀이면 내 부서·팀(관리 탭 인원 명단 기준, 겸임 A·B는 둘 다), 개인이면 내 이름과 정확히 같을 때. 작성자를 고르지 않으면 상태줄에 "작성자를 선택하면 내 것만 골라 보여줍니다"가 나옵니다.
이 화면은 카톡·네이버·시트에 아무것도 보내지 않습니다DB(공지·요청 표)와 웹푸시만 씁니다. 카톡 단톡 공지를 대신하는 화면이지, 카톡으로 다시 보내 주지는 않습니다.

  3. 상태를 바꾸면 화면이 먼저 바뀌고 저장됩니다. 실패하면 "상태 변경 실패: …" 후 원래대로 다시 읽어 옵니다.

8. 알림은 어떻게 오나

어디에무엇이언제 갱신
사이드바 "공지·요청" 빨간 숫자안 읽은 공지 + 나에게 온 대기 요청 + 내 요청 진행 소식(아직 안 본 것)2분마다 · 창으로 돌아올 때 · 앱 안에서 공지·요청이 바뀐 직후(즉시)
이 화면 상태줄 칩위 세 가지를 나눠서탭 전환·변경 직후
웹푸시(휴대폰·PC 알림)새 공지 "공지 — 제목" / 새 요청 "부서 요청 — 유형" / 진행 소식 "내 요청 처리중·완료 — 유형"올린 즉시(대상자만, 올린 본인 제외). 알림 허용을 켠 기기만
요청 카드 파란 테두리내가 보낸 요청의 상태가 바뀜부서 요청 탭을 보는 순간 "확인"으로 바뀌어 다음엔 사라짐
알림이 안 오면사이드바 오른쪽 위 작성자(본인)가 선택돼 있는지, 그리고 기기의 알림 허용(푸시 설정)이 켜져 있는지 확인하세요. 작성자가 없으면 "나에게 온 것"을 고를 수 없어 배지도 0입니다.

9. 이럴 땐 어떻게

공지를 읽었는데 빨간 숫자가 안 줄어요

읽음은 상세 창을 열었을 때 기록됩니다(목록에서 보기만 하면 아님). 그리고 작성자(본인)가 선택돼 있어야 기록됩니다. 작성자를 고른 뒤 다시 열어 보세요.

내 팀 공지인데 "내 공지"에 안 보여요

대상 팀이 내 소속(관리 탭 인원 명단의 부서·팀)과 다르게 지정된 경우입니다. "모든 공지"로 바꿔 찾아보고, 명단의 내 팀이 맞는지 관리자에게 확인하세요.

받은 요청 탭에 남이 받은 요청이 안 보여요

의도된 동작입니다. 요청은 당사자(수신 대상 또는 요청자)만 봅니다. 전체 대상 요청은 모두에게 보입니다.

실수로 완료를 눌렀어요

같은 상세 창의 [완료 취소]를 누르면 대기로 돌아갑니다(시작·완료 기록은 지워짐). 요청자에게는 "상태를 "대기"로 바꿨습니다" 알림이 갑니다.

공지를 올렸는데 팀원 폰에 알림이 안 갔어요

웹푸시는 기기에서 알림을 허용한 사람에게만 갑니다. 공지 자체는 정상 등록돼 사이드바 배지(2분 안)로는 모두에게 표시됩니다. 푸시가 실패해도 공지 등록엔 영향이 없습니다.

"부서 요청"에서 전체 공지라는 말이 보여요

대상 선택기의 첫 칩 이름이 "전체 공지"로 되어 있어서 그렇습니다. 요청에서는 "모든 재직자에게 보내는 요청"이라는 뜻으로 읽으면 됩니다.

불러오기 실패 문구가 떠요

"불러오기 실패 — supabase/dept-requests.sql 실행 여부를 확인하세요." 같은 빨간 상자가 뜨면 서버 표가 준비되지 않은 상태입니다. 관리자에게 문구를 그대로 전달하세요.
